# Signal Reclamation and Corrective Salience

**Date:** 2026-09-14  
**Status:** active tactics brainstorm

## Core problem

Systems often treat negative feedback as something to suppress as quickly as possible:

```text
friction -> remove
failure -> hide
pain -> anesthetize
error -> smooth
uncertainty -> collapse
```

That is sometimes correct. But it can also destroy the information required for adaptation.

The useful question is:

> **Does this negative signal merely impose cost, or does it carry corrective information that the system still needs?**

## Signal reclamation

Working sequence:

```text
SIGNAL
-> ATTENTION
-> UPDATE
-> CORRECTION
-> RECOMPOSITION
```

A robust system does not worship negative feedback. It preserves the signal long enough to classify it.

Possible classes:

```text
NOISE          -> discard
HARM           -> stop / protect
CORRECTIVE     -> learn
COERCIVE       -> reject authority claim
AMBIGUOUS      -> investigate
```

This adds a feedback dimension to the repo's existing safe-action and nonbinary-failure work.

## Corrective salience

Some consequences are useful because they are difficult to ignore.

Call this **corrective salience**:

> the degree to which a consequence reliably captures attention and improves the next model or action.

The key distinction is:

```text
SALIENCE != SUFFERING
```

Suffering is neither necessary nor sufficient for learning. A painful or costly consequence can be highly salient, but it can also be misleading, excessive, or merely destructive.

## Custody of consequence

A negative signal becomes dangerous when power can manufacture the signal and then declare its preferred interpretation to be the lesson.

Therefore any corrective-feedback theory needs governance questions:

- Who caused the consequence?
- Who pays the cost?
- Was the cost proportional?
- Is there an exit?
- Can the interpretation be challenged?
- Can the system distinguish naturally occurring feedback from punishment engineered to compel obedience?

Working law:

> **Correction requires legible consequence under bounded custody.**

## Relation to fail-soft precision

The Remhir counter model already shows one useful design form:

```text
excellent timing -> counter
imperfect timing -> block
badly outside envelope -> failure
```

The system preserves useful feedback without making every imperfect attempt catastrophic.

That suggests a broader tactical principle:

> Preserve enough consequence to teach the boundary, but do not make the boundary so punitive that exploration becomes irrational.

This complements the existing `safe action envelope` idea.

## Relation to uncertainty and autonomy

The earlier useful-error model asks whether an imperfect local decision still contributes.

Signal reclamation asks a second question:

> When an action fails or degrades, does the resulting feedback teach the local or global system anything useful?

A resilient system wants both:

```text
high useful-error ratio
+
high corrective-information ratio
```

A degraded action that still contributes **and** teaches is especially valuable.

## Controlled discontinuity

This theory also has a nonmilitary design analogue.

Aesthetic systems such as stop motion can preserve visible discontinuity rather than eliminating it. The discontinuity becomes information about material, process, authorship, and style.

Generalized form:

```text
negative signal + bounded interpretation = information-bearing contrast
```

This is an analogy, not historical evidence.

## Compact doctrine

> **Do not eliminate every negative signal. First determine whether it is noise, harm, coercion, or corrective information.**

Corollary:

> **A system learns best when consequence is legible, bounded, and correctable without making ordinary exploration irrational.**
